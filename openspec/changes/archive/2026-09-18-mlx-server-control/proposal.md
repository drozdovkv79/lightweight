## Why

Модели запускаются локально через `rapid-mlx` / `mlx_lm`, но сейчас их серверы приходится поднимать вручную в терминале. Управление сервером должно жить в тулбаре рядом с выбором модели: пикер сервера, старт/стоп одной иконкой, окно лога.

## What Changes

- Тулбар (справа от меню модели): пикер сервера (`rapid-mlx` / `mlx_lm`), кнопка старт/стоп одной иконкой (play/stop с состоянием), рядом с настройками — кнопка лога одной иконкой.
- Старт: `rapid-mlx serve {модель} --port 8008 --max-tokens 65000` или `mlx_lm.server --model {модель} --port 8008 --max-tokens 65000` (бинарник из PATH); вывод — в лог.
- После старта `provider_url` автоматически переключается на `http://127.0.0.1:8008/v1/chat/completions`.
- Стоп: остановка запущенного серверного процесса + добивка остатков на порту 8008 для освобождения памяти.
- Отдельное окно с консольным выводом запущенных серверов (моноширинный, автоскролл).

## Capabilities

### New Capabilities

- `mlx-server-control`: пикер rapid-mlx/mlx_lm, старт/стоп серверов из тулбара, окно лога.

### Modified Capabilities

- `provider-config`: `provider_url` автоматически выставляется на локальный сервер при старте (существующий сценарий ручной настройки не меняется).

## Impact

- `LightweightChat/Sources/ContentView.swift` — тулбар: пикер, кнопки, окно лога.
- `LightweightChat/Sources/ChatViewModel.swift` (или новый `ServerManager`) — запуск/останов `Process`, чтение stdout/stderr в лог, состояние running/stopped, запись `provider_url`.
- Внешние зависимости: бинарники `rapid-mlx` / `mlx_lm.server` в PATH; порт 8008.
