## Context

`SelectionLog` был добавлен как диагностика при разработке цепочки selection-триггера (`fix-selection-trigger-reliability`). После отладки и финальной сборки (`Build complete`, `swift test` passing) он больше не нужен: цепочка работает, баги исправлены, логирование — лишь шум в unified logging.

`Logger(subsystem: "org.peterc.lightweight", category: "SelectionAssistant")` + `NSLog` пишутся в систему даже при отсутствлении багов. Для macOS-приложения, которое распространяется как .app, это ненужные записи, растущие по объёму логов.

## Goals / Non-Goals

**Goals:**
- Убрать весь `SelectionLog` из кода. Файл удалён полностью, вызовы убраны.
- Код компилируется без warning/error.

**Non-Goals:**
- Не трогать другое логирование (при необходимости оно добавится отдельным change).
- Не изменять поведение цепочки триггера.

## Decisions

**D1.** Полное удаление `SelectionLog` — не оставить даже пустой enum (удаление файла проще, чем комментирование).

**D2.** Вызовы заменяются на пустые строки (удаление строк целиком), а не пустыми функциями-обёртками (меньше шума в коде, нет dead code).

## Risks / Trade-offs

- Потеря диагностики при будущих багах в цепочке триггера. Если что-то снова сломается — добавить `SelectionLog` заново (это быстро).
- Нет риска для runtime: `SelectionLog` не влияет на логику.
